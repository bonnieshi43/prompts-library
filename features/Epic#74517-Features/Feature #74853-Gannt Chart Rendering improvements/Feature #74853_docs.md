# 1 Feature Summary

**核心目标**：改进 Gantt 图表的坐标轴渲染方式，使甘特条从坐标轴起点开始绘制（无间隙）、标签居中显示在刻度之间（类目轴风格）、网格线与数据带对齐。
**用户价值**：解决当前 Gantt 图表在轴起点存在视觉空隙、日期标签与时间刻度对齐生硬（不直观）、网格线与实际数据条带错位的问题，提升甘特图的可读性与专业度。

- 脚本兼容性：脚本中读写 labelBetween 属性
- 本地化：Gantt 任务/里程碑标签的本地化文本显示
- 配置检查：本次改动未涉及 SreeEnv/defaults.properties

# 4 Special Testing

仅当 Feature 需要测试时执行。

## Security
- 脚本入参校验

## Performance
- 不涉及

## Compatibility
- 向后兼容性：`fixGanttCoord` 中删除了对 `AxisDescriptor` 自定义属性（颜色、可见性、高亮、截断、文本格式）的应用逻辑，需验证替代机制是否完全承接原有能力

## 本地化
- `GanttGraphGenerator` 中移除的 `Tool.localize(label)` 调用需验证 Gantt 任务/里程碑标签的本地化文本显示是否受影响（尤其在非默认 locale 及 SQL Server Cube 数据源场景）

## script
- `AxisSpec.isLabelBetween()`/`setLabelBetween()` 已标注 `@TernMethod`，需验证脚本中可正常调用该 API 设置/读取，且对非 Gantt 图表脚本行为无副作用
- Auto-complete 是否能识别新方法

## 文档/API
- `AxisSpec.isLabelBetween()` 的 Javadoc 声称"N 个刻度产生 N-1 个标签"，与 `DefaultAxis` 实际实现（要求标签数等于刻度数、末位用轴末端补位）不符，需要与产品/知识库文档核对甘特图标签-刻度对应关系的正确定义

## 配置检查
- 本次改动未涉及 `SreeEnv`/`defaults.properties`，可不做该项

# 5 Regression Impact（回归影响）

可能受影响模块：

- **Chart**：图表核心引擎（`AxisSpec`/`DefaultAxis`/`Scale`/`Coordinate`）—— 影响所有使用 `AxisSpec` 的图表类型，需做非 Gantt 图表的回归冒烟
- **GanttGraphGenerator**：Gantt 图表专属渲染路径
- **Export**：打印预览及 PDF / Excel / Image 导出中的坐标轴、网格、标签对齐效果
- **Script**：脚本/表达式引擎（`AxisSpec` 新增 `@TernMethod`，可被 Groovy 脚本调用）
