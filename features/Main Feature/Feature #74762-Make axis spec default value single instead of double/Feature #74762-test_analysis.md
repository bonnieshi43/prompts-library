# Feature #74762 - Make Axis Spec Default Value Single Instead of Double

## 一、需求分析（Requirement Analysis）

### 1. 功能理解与范围

- 核心目标：将 `AxisSpec` 的坐标轴样式（`style`）默认值由 `AXIS_DOUBLE`（主轴 + 对侧轴，双轴线）改为 `AXIS_SINGLE`（单轴线），避免简单图表默认呈现"四边封闭的盒子"效果。
- 涉及模块：Chart Engine 坐标轴模型层（`AxisSpec`），属于图表渲染的基础默认值改动，理论上影响所有未显式设置 `axisStyle` 的图表坐标轴渲染。
- 功能类型：渲染默认行为变更（UI / Rendering Default）。

### 2. 需求清晰度与完整性

- 需求描述明确了"为什么改"（简单图表不需要盒子效果）和"改什么"（默认值 double → single），但未定义：
  - 该默认值变更的**生效范围**：是仅对"新创建的图表/坐标轴"生效，还是对所有未显式设置 `axisStyle` 的既有（历史保存）图表同样生效；
  - 是否所有图表类型（Line/Bar/Area/Point/Facet/组合图/双 Y 轴图等）都应统一采用单轴默认值，还是仅"简单图表"场景需要，某些图表类型（如需要对侧轴标签的 Facet 图、双值轴组合图）可能依赖双轴默认行为；
  - 是否需要提供迁移/兼容策略，保证已存在的图表视觉效果不因升级而"无声改变"。
- 需求未提及历史数据兼容性问题，而该字段是否在已保存的图表定义中被显式持久化（从而不受默认值变化影响）需要通过测试验证，不能假设实现已妥善处理。

### 3. 测试风险识别

- 行为误解风险：改动是全局默认值级别的改动（`private int style = AXIS_DOUBLE` → `AXIS_SINGLE`），影响面并非局限于某一类图表，而是所有未显式调用 `setAxisStyle()` 的坐标轴。
- 跨模块影响风险：`AxisSpec` 被所有图表类型（Line、Bar、Area、Point、Facet、组合图等）的坐标系统复用，需要逐类型验证是否有非预期的轴线消失（尤其依赖对侧轴标签的场景，如 Facet 图顶部轴、双 Y 轴组合图）。
- 状态一致性问题（核心风险）：需要确认**已保存/已存在的图表定义**在升级后加载时，`style` 字段的实际取值来源——如果历史图表定义中该属性因"等于默认值而未被显式持久化"，则升级后加载会得到新默认值 `AXIS_SINGLE`，导致历史图表外观在用户无感知的情况下发生变化；如果该字段总是被显式持久化（不论是否等于默认值），则历史图表不受影响，只有全新创建的图表/坐标轴使用新默认值。此点必须通过实际的新旧版本加载对比测试来确认，不能凭代码假设。
- 兼容性风险：升级前后同一图表模板/报表在无任何用户操作的情况下，渲染效果是否发生变化。

## 二、实现分析（Implementation Analysis）

### 1. 改动类型（Change Type Identification）

- Optimization / 默认值调整（Default Value Change）。
- 影响层级：数据模型层默认值（`AxisSpec.style` 字段初始值），间接影响渲染层（坐标轴线绘制数量与位置）。
- 改动本身极小（单行字面量变更），但由于 `AxisSpec` 是被广泛复用的基础坐标轴配置类，实际影响面是**跨图表类型的默认视觉表现**，而非某个具体功能模块。

### 2. 需求实现一致性

- 已覆盖的核心功能：`style` 字段默认值由 `AXIS_DOUBLE`（0x3，双轴：主轴 + 对侧轴）改为 `AXIS_SINGLE`（0x1，单轴），直接对应需求"默认不再呈现双轴/盒子效果"的诉求。
- 需要重点验证的一致性问题：
  - 需求描述的场景是"simple graphs"（简单图表），但实现是在 `AxisSpec` 类的字段默认值层面全局生效，并未区分图表类型或坐标系统类型（Rect / Facet / Polar 等），需要验证是否所有图表类型都符合"改为单轴更合理"这一预期，还是存在需要保留双轴默认表现的例外场景（如需要对侧轴标签展示的 Facet 分面图、双值轴组合图）。
  - `getAxisStyle()` 实际返回值还受 `labelOnSecondaryAxis` 标志影响（`labelOnSecondaryAxis ? (style | AXIS_LABEL_OPPOSITE_SIDE) : style`），本次改动未触及该逻辑，需要验证默认值变更后与 `labelOnSecondaryAxis` 的组合行为仍然正确。
- 隐式行为变化（需要重点排查）：
  - 本次 PR 未包含任何版本迁移/兼容性处理代码（无 `readObject`/序列化版本升级/XML 默认值迁移逻辑），需要通过实际测试确认：**该字段在图表定义持久化（保存/加载）时是否总是被显式写入实际值**。若答案是"否"（即历史保存的定义中该属性因等于旧默认值而被省略未写入），则本次改动会导致所有历史图表在下次加载时"无声"从双轴变为单轴，这是一个需要产品/QA 共同确认是否可接受的重大行为变化，而非单纯的新建图表默认值调整。

### 3. 关键实现风险

1. **历史图表默认值兼容性风险（最高优先级）**：本次改动没有附带任何迁移代码，若持久化机制存在"等于默认值时省略字段"的优化策略，所有历史图表/报表模板在升级后会静默改变坐标轴外观（双轴变单轴），且用户无法感知改动原因。
2. **跨图表类型回归风险**：`AxisSpec` 被所有图表类型复用，需要验证 Facet 分面图（依赖顶部对侧轴展示分面标签）、双 Y 轴组合图、Polar/雷达图等原本可能依赖双轴默认表现的图表类型是否因本次默认值改动而丢失必要的轴线/标签。
3. **`labelOnSecondaryAxis` 组合风险**：`getAxisStyle()` 中默认值变更后与 `labelOnSecondaryAxis` 标志位或运算的组合结果需要重新验证（如 `AXIS_SINGLE | AXIS_LABEL_OPPOSITE_SIDE` 是否等价于合理的枚举值 `AXIS_SINGLE2`，还是产生未在常量列表中定义的组合值）。
4. **脚本/模板层面覆盖遗漏风险**：若产品内置的图表模板、示例报表或脚本生成的图表中有依赖"未显式设置轴样式即为双轴"这一隐含约定的逻辑（例如某处判断轴数量或轴位置），需要验证这些内置资源未被破坏。

## 三、测试设计（Test Design）

### 3.1 风险驱动测试策略

- 本次改动的核心风险并非改动本身的正确性（单行默认值修改无逻辑复杂度），而是**默认值变化对已有历史数据与跨图表类型的连锁影响**，测试重点应放在"影响范围核实"而非"新建图表下的功能验证"。
- 风险影响范围：潜在覆盖所有未显式设置 `axisStyle` 的图表坐标轴，包括历史已保存的图表/模板。
- 状态一致性问题：需要专项验证历史图表升级后是否保持原有双轴外观，这是本次改动最关键的验证点。
- 默认行为变化：这正是本次改动的目的（新建简单图表默认单轴），需要在预期变化（新图表）与非预期变化（历史图表被动改变）之间划清界限并分别验证。

### 3.2 必要测试类别

#### 功能验证（Functional）

- **Why**：验证新建图表在未显式设置轴样式时，默认呈现单轴效果，满足需求描述的"简单图表不再是盒子"诉求。
- **Scope**：新建 Line/Bar/Point/Area 等常见简单图表，不设置 `setAxisStyle`。
- **Validation Goal**：坐标轴仅在主轴一侧（如左侧 Y 轴、底部 X 轴）显示轴线，对侧无轴线，图表不再呈现四边封闭的盒子效果。

#### 回归测试（Regression）

- **Why**：`AxisSpec` 是被广泛复用的基础类，需验证除简单图表外的其它图表类型未因默认值改动而产生非预期视觉回归。
- **Scope**：Facet 分面图（含顶部对侧轴标签场景）、双 Y 轴组合图（Combination Chart with dual value axis）、Polar/雷达图、已显式调用 `setAxisStyle(AXIS_DOUBLE)` 的图表。
- **Validation Goal**：显式设置了轴样式的图表不受本次默认值改动影响；依赖对侧轴标签的图表类型（如 Facet 图顶部轴）仍能正确显示必要的轴线/标签，未因默认值改动而丢失。

#### 兼容性测试（Compatibility）

- **Why**：本次改动未包含迁移逻辑，是本次分析中优先级最高的风险点，必须专项验证历史数据兼容性。
- **Scope**：使用改动前版本创建并保存、且未显式设置 `axisStyle` 的图表/报表模板，在新版本环境下重新打开/刷新/导出。
- **Validation Goal**：明确得出结论——历史图表升级后坐标轴外观是保持原有双轴效果（字段被显式持久化，不受默认值变化影响），还是变为单轴（字段依赖默认值，受到影响）。无论结果如何，都需要将结论同步给产品/PM 确认是否符合预期；若为"无声改变历史图表外观"，应作为高优先级问题反馈，而非视为默认已解决。

#### 边界与异常（Boundary）

- **Why**：`getAxisStyle()` 的返回值同时受 `style` 默认值与 `labelOnSecondaryAxis` 标志共同决定，改动后的组合值需要重新确认。
- **Scope**：`labelOnSecondaryAxis = true` 且未显式设置 `axisStyle` 的坐标轴。
- **Validation Goal**：`AXIS_SINGLE | AXIS_LABEL_OPPOSITE_SIDE` 组合后的实际渲染效果（轴线位置、标签位置）符合预期，不产生轴线缺失或标签错位。

#### 自动化测试建议

- Unit：`new AxisSpec().getAxisStyle()` 默认返回值断言由 `AXIS_DOUBLE` 更新为 `AXIS_SINGLE`；`labelOnSecondaryAxis` 与新默认值组合后的返回值断言。
- Integration：各图表类型（Line/Bar/Facet/组合图）在不显式设置轴样式时的坐标轴渲染结构验证。
- E2E：历史报表模板（改动前保存）升级后的可视化回归对比（改动前 vs 改动后截图 diff），重点比对坐标轴显示。

## 四、关键测试场景（Key Test Scenarios）

### Scenario 1：新建简单图表默认单轴效果验证

- **Scenario Objective**：验证新建的简单图表（如 Line/Bar）在不显式设置轴样式时，默认仅显示单侧轴线，不再呈现盒子效果。
- **Scenario Description**：这是本次需求的核心诉求，若默认值未生效，简单图表仍会显示不必要的双轴封闭效果，需求未达成。
- **Key Steps**：
  1. 新建一个简单 Line 或 Bar 图表，不对坐标轴做任何脚本/样式设置。
  2. 查看图表渲染效果。
- **Expected Result**：X 轴、Y 轴均只在主轴一侧显示轴线（如左、下两侧），对侧（右、上）无轴线，图表不再是四边封闭的盒子形态。
- **Risk Covered**：核心需求功能验证。
🔴 **测试-分析**：默认显示没有问题，设置 set labels on opposite sider 在y轴有Bug #75649，设置在x是好的


### Scenario 2：历史图表升级后坐标轴外观兼容性验证（最高优先级）

- **Scenario Objective**：验证在本次改动上线前创建并保存、且未显式设置轴样式的历史图表/报表模板，升级后重新打开时的坐标轴外观是否发生非预期变化。
- **Scenario Description**：本次改动未包含任何迁移/兼容处理代码，若历史图表定义依赖字段默认值（而非显式持久化实际值），会导致所有历史图表在用户无操作、无感知的情况下从双轴变为单轴，这是需要重点排查的高风险点。
- **Key Steps**：
  1. 使用改动前版本创建一个未显式设置轴样式的图表并保存为报表/模板。
  2. 升级到包含本次改动的版本。
  3. 重新打开/刷新该报表，观察坐标轴显示效果是否与升级前一致。
- **Expected Result**：需要明确得出结论并与产品对齐——历史图表是否保持原有双轴外观。若外观发生了无预期的静默变化，应作为兼容性问题上报。
- **Risk Covered**：历史数据兼容性风险（本次改动的最高优先级风险）。

🔴 **测试-分析**：符合预期

### Scenario 3：显式设置双轴样式的图表不受影响验证

- **Scenario Objective**：验证已显式调用 `setAxisStyle(AXIS_DOUBLE)`（或等效脚本/UI 配置）的图表，其坐标轴效果不受本次默认值改动影响。
- **Scenario Description**：默认值改动理论上只影响未显式设置的场景，需验证显式配置的优先级仍然正确，未被默认值覆盖。
- **Key Steps**：
  1. 创建一个图表，通过脚本显式调用设置为双轴样式。
  2. 查看渲染效果。
- **Expected Result**：该图表仍然按双轴样式渲染（主轴 + 对侧轴均显示），不受默认值变化影响。
- **Risk Covered**：显式配置优先级回归风险。

🔴 **测试-分析**：有两个dim的不受影响，有两个measue的如果设置secondary axis有Bug #75646

### Scenario 4：依赖对侧轴的复杂图表类型回归验证

- **Scenario Objective**：验证 Facet 分面图（依赖顶部对侧轴展示分面信息）、双 Y 轴组合图等原本可能隐式依赖双轴默认表现的图表类型，未因本次默认值改动而丢失必要的轴线或标签。
- **Scenario Description**：`AxisSpec` 被所有坐标系统复用，简单图表的改进不应以牺牲复杂图表类型的正确显示为代价。
- **Key Steps**：
  1. 创建一个 Facet 分面图表（多个子图并排/上下排列），不显式设置轴样式。
  2. 创建一个包含双 Y 轴（主/次值轴）的组合图，不显式设置轴样式。
  3. 分别观察坐标轴与标签的显示效果。
- **Expected Result**：Facet 图各分面所需的轴线/标签正常显示，不因默认值改为单轴而缺失关键信息；双 Y 轴组合图若业务上需要保留两侧轴线，应确认是否有专门的显式设置来保障（而非依赖默认值），且现有此类图表模板未出现轴线缺失回归。
- **Risk Covered**：跨图表类型回归风险。

### Scenario 5：labelOnSecondaryAxis 与新默认值组合验证

- **Scenario Objective**：验证 `labelOnSecondaryAxis` 为 `true` 且未显式设置轴样式时，`getAxisStyle()` 返回的组合值渲染效果正确。
- **Scenario Description**：`getAxisStyle()` 的实际返回值由 `style` 默认值与 `labelOnSecondaryAxis` 标志共同决定，默认值改变后需要确认该组合逻辑仍然产生合理的渲染效果，而非遗留的仅针对 `AXIS_DOUBLE` 场景设计的隐含假设。
- **Key Steps**：
  1. 创建一个图表并将其 `labelOnSecondaryAxis` 设置为 `true`，不显式设置 `axisStyle`。
  2. 观察坐标轴线与标签的显示位置。
- **Expected Result**：轴标签正确显示在对侧（次轴）位置，轴线数量与位置符合单轴+对侧标签的预期组合效果，无标签错位或轴线缺失/多余。
- **Risk Covered**：默认值与标志位组合的边界风险。

🔴 **测试-分析**：Bug #75646

### Scenario 6：导出/打印场景下坐标轴效果一致性验证

- **Scenario Objective**：验证默认单轴效果在 PDF/Image 导出与 Print Layout 预览中与页面显示保持一致。
- **Scenario Description**：坐标轴渲染逻辑通常被导出/打印路径复用，需确认默认值改动在这些路径下同样生效，不存在导出结果仍显示旧双轴效果的不一致情况。
- **Key Steps**：
  1. 创建一个使用默认轴样式的简单图表。
  2. 分别执行 PDF 导出、Image 导出与 Print Layout 预览。
- **Expected Result**：导出/打印结果中坐标轴均为单轴效果，与页面显示一致。
- **Risk Covered**：导出/打印场景下渲染一致性风险。

🔴 **测试-分析**：导出和prview一致
