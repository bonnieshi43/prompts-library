# 文档负责人：AI 检索优化 Review 指南

> **目标读者**：负责维护 StyleBI 用户文档的内容工程师，不需要了解 AI 或代码细节。
>
> **你需要做什么**：对照 AI 给出的优化清单，判断每篇文档是否需要调整结构，并按照本指南的原则进行修改。

---

## 第一步：理解"为什么要调整结构"

AI 助手在回答用户问题时，不是读取整篇文档，而是读取文档的**片段（chunk）**。

- 每个 chunk 大致对应文档中的一个 `== H2` 章节（或整篇，如果文档没有 H2）
- 如果一个 chunk 太长，AI 很难准确定位到其中的某个具体细节
- 如果 chunk 的边界切错了，AI 拿到的内容缺少必要的上下文，给出的回答可能不完整

**一个理想的 chunk**：
- 独立、完整，能回答一个具体的用户问题
- 大小适中（大约 600~1000 词，不超过 1500 词）
- 不依赖"上一个 chunk 里写了什么"才能被理解

---

## 第二步：看懂清单里的指标

优化清单会给出每个文档的以下信息：

| 指标 | 含义 |
|------|------|
| `maxTok` | 预估最大 chunk 大小（字符数除以 4）。> 1200 = 高危 |
| `noH2` | 文档没有 `==` 二级标题，整篇是一个大 chunk |
| 文档类型 | 操作流程类 / 参考查阅类 |

---

## 第三步：判断文档类型

我们的非script文档分两类，类型决定了应该怎么改。

---

### 如何判断？

**核心问题：用户拿到这篇文档，是在"按步骤做一件事"，还是在"查某个配置项是什么意思"？**

```
用户是在跟着步骤操作吗？
（文档里有 Step 1, 2, 3... 或 ". 操作一、操作二..."这样的有序流程）
├── 是 → 操作流程类
│         → 见第四步（操作流程类）
│
用户是在查某个属性/参数选项的说明吗？
（文档里主要是属性表格、选项列表、参数解释）
└── 是 → 参考查阅类
          → 见第四步（参考查阅类）
```

**注意**：图表类文档（如 `RadarChart.adoc`）和概念解释类文档（如 `CompareDataByDate.adoc`）里面本质上也是操作步骤，都归入**操作流程类**。

---

## 第四步：按类型决定怎么改

---

### 操作流程类

**典型文件**：`AddConditions.adoc`, `AddTargetLineTrendLine.adoc`, `RadarChart.adoc`, `CompareDataByDate.adoc`, `AddCrosstab.adoc` 等

**问题**：可能是 `noH2`（整篇超大），也可能是某个 H2 内的步骤太多太长。

---

#### 情况 1：文档没有 H2 → 先判断内容是否真的可以拆

**核心判断问题**：

> 文档里有没有某一块内容，**用户可以跳过其他部分、单独来查它**？

- 如果整篇是一套从头到尾的操作流程（步骤 1 → 步骤 N 全部连贯），**不需要加 H2**。整篇一个 chunk 反而是正确的，保证步骤上下文完整。
- 如果文档里有几个**彼此独立**的子任务（比如"创建"和"格式化"和"筛选"），**才需要加 H2**，每个独立任务一个 H2。

**独立任务测试**：

> 如果用户不做前一个任务，可以直接从这里开始操作吗？
> - **可以** → 适合做 H2 边界
> - **不可以**（必须先完成上一步才能进行这步）→ 不应该做 H2 边界

**示例**：

```adoc
// ✅ 有多个独立任务 → 加 H2
== Add a Crosstab           ← 可以单独做：创建交叉表
== Format the Crosstab      ← 可以单独做：不创建也能改格式（已有表格时）
== Filter Data in Crosstab  ← 可以单独做：筛选是独立操作

// ✅ 全篇是一套连贯流程 → 不加 H2，保持整篇一个 chunk
（WordcloudChart.adoc 全部是 chart binding 步骤，不拆）
```

---

#### 情况 2：有 H2 但某个 H2 内内容太长

先检查这个 H2 里的操作步骤是否是连续编号。如果是，**不要用 H3 打断步骤**。

只有以下内容才适合提取为 H3：
- 步骤之外的大段参数说明（与步骤相对独立）
- 步骤之外的独立使用说明
- 步骤之外的 NOTE / 补充内容块

**🚫 不要这样做**（来自 `AddTargetLineTrendLine` 的修改，是反面教材）：

```adoc
== Add a Target Line
. Step 1: 右键打开属性面板
. Step 2: 选择 Advanced Tab
. Step 3: 选择 Line Tab
. Step 4: 选择 Field

=== Set the Value       ← ❌ 用 H3 把步骤 5、6 切断出来
[start=5]               ← ❌ 需要靠 [start=5] 维持编号，本身就是破坏性信号
. Step 5: 填写值
. Step 6: Entire Chart 选项

=== Set the Label       ← ❌ 步骤 7、8 脱离了"先完成步骤 1-6"的上下文
```

**✅ 正确做法**：步骤保持完整，不加 H3 拆断：

```adoc
== Add a Target Line
. Step 1: 右键打开属性面板
. Step 2: 选择 Advanced Tab
. Step 3: 选择 Line Tab
. Step 4: 选择 Field
. Step 5: 填写值
. Step 6: Entire Chart 选项
. Step 7: 选择 Label
. Step 8: 自定义 Label
. Step 9: 选择 Line Style
. Step 10: 确认
```

---

### 参考查阅类

**典型文件**：`ChartProperties.adoc`, `AxisProperties.adoc`, `VisualFormat.adoc` 等

**特征**：用户不是从头读，而是直接跳到某个属性查含义。每个属性/选项之间相对独立。

**问题**：H2 内有大量属性描述，单块太长。

**怎么改**：对属性较多的 H2，按**属性的功能分组**加 H3：

```adoc
== Advanced Tab
=== Chart Display Options       ← 一组相关属性
=== Trend Line Settings         ← 另一组相关属性
=== Plot Axis Configuration     ← 第三组
```

**参考类文档可以放心加 H3**，因为每个属性组是独立的，用户查任何一组都不需要先看其他组。

---

## 第五步：Review 检查清单

对优化清单里的每个文件，按以下顺序确认：

**Step 1 — 需要改吗？**
- [ ] 文件 > 3KB（< 3KB 系统不会切割，不需要改）
- [ ] 清单标记 maxTok > 1000 或 noH2=true
- [ ] 文档内容确实有**多个可以独立查阅的主题**（如果整篇是一套连贯流程，即使大也不改）

三项都满足，进入 Step 2。**有任何一项不满足，跳过这个文件。**

**Step 2 — 判断文档类型**（操作流程类 / 参考查阅类）

**Step 3 — 确认 H2 边界合理性**
- [ ] 每个 H2 代表一个"用户可以独立完成的任务"或"可以独立查阅的主题"
- [ ] H2 划分不是根据同一个流程的"阶段"（Set the Value / Set the Label），而是根据彼此独立的任务

**Step 4 — 确认 H3 使用合理性**（如果你打算加 H3）
- [ ] 操作流程类：H3 没有插在连续步骤列表中间
- [ ] H3 标题带有足够的上下文（避免泛化名称如 "Set the Value"）
- [ ] H3 内容可以独立理解，不依赖"前一个 H3 里写了什么"

**Step 5 — 修改后自检**
- [ ] 把修改后的文档里任意一个 H2 或 H3 的内容单独复制出来
- [ ] 问自己：只看这段内容，能明白它在描述什么功能、怎么操作吗？
- [ ] 如果答案是"不能，需要看上面的内容"→ 说明切分太细，需要合并

---

## 附录：常见标题命名对比

| ❌ 不好的 H3 标题（太泛，脱离上下文无意义） | ✅ 好的 H3 标题（带上下文，可独立理解） |
|----------------------------------------|--------------------------------------|
| `=== Set the Value` | `=== Target Line Value Options` |
| `=== Set the Label` | `=== Customizing the Target Line Label` |
| `=== Options` | `=== Plot Display Options` |
| `=== Step 1` | （不要用 H3 来表示步骤） |
| `=== Configure` | `=== Configure Axis Scale Settings` |
